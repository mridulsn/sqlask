sqlask

Ask a database a question in plain English. A model writes one SQLite SELECT, a read-only guard checks it, SQL errors and suspicious empty results go back to the model for another try, and you get a short answer plus the exact query used.

question›schema summary›model writes SQL›read-only guard›execute›retry on error (max 3)›answer + SQL

    Eval scoreboard
    
      
    
    
    
    
    Execution accuracy on 40 questions with hand-written gold queries: a run counts as
      correct when its result rows equal the gold result (order ignored unless the question asks for one,
      numbers rounded to 2 decimals, extra columns allowed).
    
    
    
      
    
    
    
    
    Schema "full" is the prompt the pipeline normally uses: tables, columns, types, keys and a few
      sample values per column. "bare" drops the sample values (an ablation on the 6 questions most likely to need
      an exact stored value). Retried counts questions that needed more than one attempt; "x2" in the table below
      marks them. Strict also requires the same number of columns as the gold query.
    
    
    Both models scored 40 of 40, so this set does not separate them, and the retry loop
      rarely had to fire. Chinook is a very widely used sample database and the models write defensive filters
      for it (LIKE '%hip%hop%', IN ('United Kingdom', 'UK')) even with no sample
      values in the prompt. The four demo prompts above show the retry loop doing real work.
